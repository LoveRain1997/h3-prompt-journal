# Case Study 027 — 一张图 + 一首歌，双人对口型 MV 完整 H3 提示词（Full-Reference 六字段 · 选择性唱口 · 24 个对口型窗口）

> 一支约 215 秒的**真人古装奇幻爱情 folk 对唱 MV**，只靠**一张双人定妆图 `<Picture 1>` + 整首歌**，按歌词感知切点切成 **17 段独立可生成**的 H3 提示词。每段都是 self-contained：喂**同一张定妆图（只锁人物身份与服装）+ 该段对应裁剪音频 `<Audio 1>`** 即可单独出片；全局时间只用来标注「源歌窗口」，**每段动作时间轴一律从 0.000 重新计时（local time）**。
>
> 这套打法的核心是：**音乐时间轴驱动一切**——先用歌词感知切割把整首歌切成绝不切断唱句的 10–15 秒分段，再严格按切片 JSON 的 `vocal` 标签把人声绑定到固定 Subject，只在导演选定的关键句启用可见对口型，其余歌词仍在原音轨播放、画面不做逐字口型；同时用**参考图唯一身份权威 + 空手表演硬保护**，杜绝模型换脸、换装、添人、加武器。
>
> 完整中文工作流与字段详解见 [`methodology.md`](./methodology.md)；17 段可直接粘贴的英文提示词见 [`prompt.md`](./prompt.md)。

## Inputs（输入）

- **PICTURE 1（唯一人物身份/服装参考）**：一张同时包含两位主角的双人合照。**只锁人物身份、五官、发型、身形与服装**，不锁场景、姿势、构图、光线；合照背景与站姿不复制，场景可按每段剧情自由重绘。
- **AUDIO 1（每段一段，唯一时间/节奏/重音权威）**：每段喂对应的**裁剪音频**（`seg01 … seg17`），**不要一次喂整曲**；音频以 `fully_copy` 保持原样，不重唱、补和声、变速、循环、重混或重启。
- **素材 manifest**：`cuts_manifest.json`（给出每段文件名、全局源歌窗口、字位 `lyric_events`、节拍 `beats` 与人声 `vocal` 标记）。
- 逐字提示词：[`prompt.md`](./prompt.md)（17 段 self-contained 英文 prompt）。
- 方法论与 JSON 字段详解：[`methodology.md`](./methodology.md)。

## 核心方法：每段 self-contained + 选择性唱口 + 音乐连续

长片切 17 段后最容易出错的是「时间越界」「音乐重启」和「两人同时乱对嘴」。本案例的纪律：

1. **每段独立可复制**：各自声明 `Picture 1` / `Audio 1` / 段时长 / 段内时间轴，单段即可生成、不依赖上下文。
2. **段内时间从 0.000 起算**：所有动作时间戳是 local time，全局时间只出现在段首「源歌窗口」说明里。
3. **只喂该段裁剪音频**：`Audio 1` 对应本片段窗，音乐天然连续；以 `fully_copy` 不重启、不加声音。
4. **选择性对口型**：68 句只选 24 句做可见唱口；每个唱口直接写在实际 `SHOT` 内，严格使用 JSON 的 `vocal` 标签。
5. **段末写 hand-off 状态**：每段结束的身体/镜头状态是下段开场可自然承接的起点，相邻段不硬切归零。

## 参考图身份权威与对口型规则

- `Picture 1` 是人物身份与服装的**唯一**来源；文字只负责新设计的动作、镜头与场景，不据歌词擅自换装、添道具、加人、改场景。
- **单人唱口单人可见**：Female 事件只让 S1（紫兰）对嘴，Male 事件只让 S2（悟空）对嘴；另一人优先出画，其次用背面、肩后轮廓或嘴部不可辨认的远景。
- **唯一真实 Duet**：仅 Segment 13 的局部窗口 `00:03.564–00:06.189` 允许两人同框、两张嘴同时同步；相邻独唱不扩展为双人唱口。
- **唱口镜头稳定**：歌词开始前先建立构图，固定距离、焦段与构图的中近景/近景，不绕脸环拍、不快速变焦、不在唱词中途切镜；嘴唇、下颌、下巴清晰可读。
- **空手表演**：两人双手全程自然放松、为空，可牵手、触碰、倚靠固定建筑；不自行添加武器。
